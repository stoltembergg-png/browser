# ADR-001 — Rust toolchain and dependency baseline

- **Status:** accepted for M0 toolchain baseline; OS matrix/MSRV and dependency allowlist remain open
- **Date:** 2026-08-11
- **Owners:** repository maintainers
- **Authority:** accepted only for the checked-in M0 toolchain baseline; it cannot satisfy product/release gates
- **Related plan:** PR-004/PR-005

## Context

The approved architecture names Rust as the primary implementation language. PR-004 now provides a real workspace, so the M0 toolchain can be pinned without claiming product or OS readiness.

## Proposed decision

Use Rust for browser-core, adapters and validation tooling. Pin Rust `1.97.1` with minimal profile plus `rustfmt` and `clippy`; use edition `2021`, resolver `2`, version `Cargo.lock`, and require locked builds. Keep production dependencies separated from dev-only test support and forbid unsafe code by default. OS support matrix, formal MSRV and dependency allowlist remain open pending runner evidence.

## Alternatives

| Alternative | Reason not selected now |
|---|---|
| Pin a toolchain immediately from memory | No evidence for the target workspace/Servo revision; may encode stale assumptions. |
| Do not pin toolchain or lockfile | Fails reproducibility and makes CI/release identity unverifiable. |
| Use another primary language | Conflicts with the approved plan and requires a new architecture decision. |

## Evidence required for ratification

- clean checkout workspace metadata — satisfied by PR-004;
- locked build/check evidence — satisfied by PR-004;
- toolchain/edition/resolver result — satisfied for M0 by `rust-toolchain.toml` and `Cargo.toml`;
- dependency source/license/advisory report;
- reference-platform and intended OS matrix result;
- architecture graph consistency;
- owner/reviewer approval and supersession path.

Missing, skipped or stale evidence keeps the open OS/MSRV/dependency portions unresolved and blocks dependent product claims.

## Consequences

Positive: reproducible dependency review and explicit supply-chain ownership. Cost: toolchain updates need policy review and may require forward-fix. No license, Servo revision, Tauri surface or process model is decided here.

## Security and rollback

Dependency advisories, malicious source changes or expired exceptions are fail-closed. Roll back to the last verified toolchain/lockfile or forward-fix the vulnerable dependency; do not silently relax advisory/license checks.
