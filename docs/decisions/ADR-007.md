# ADR-007 — typed Tauri IPC and capability-scoped privileged UI

- **Status:** proposed
- **Date:** 2026-08-14
- **Owners:** repository maintainers
- **Related PRs:** PR-021, PR-024, PR-045
- **Related threats/tests:** TM-002, TM-009, privileged caller-context negative suite, CSP/capability fixture

## Contexto

A janela Tauri é uma superfície privilegiada para o chrome do browser, não para conteúdo web. O frontend local precisa de uma forma rastreável de solicitar comandos ao core sem ganhar acesso genérico a filesystem, process, network, plugins ou a uma página carregada remotamente.

O contrato de envelopes de PR-021/024 já rejeita JSON malformado, variantes desconhecidas, versões erradas, payloads grandes, request IDs duplicados e escopos de tab incorretos. Faltava materializar o mapa de capabilities, retirar `unsafe-inline` da CSP e validar o caller contra a origem, janela, frame e generation da UI privilegiada.

## Decisão

A UI privilegiada usa somente comandos/eventos tipados e allowlisted. O shell local é a única origem autorizada (`http://tauri.localhost`), somente a janela `main` e somente o frame top-level podem entrar no boundary IPC. A generation precisa coincidir com a generation esperada antes de qualquer validação/efeito.

A capability `main-window` inicia com uma lista de permissões vazia. Nenhum plugin de filesystem, shell/process, HTTP/network, SQL ou comando Tauri genérico é habilitado por herança. Uma capability futura só pode ser adicionada com nome explícito, janela/webview alvo, threat boundary, teste negativo e revisão desta ADR/mapa.

A CSP do shell é local-only: scripts e estilos vêm de assets empacotados; `unsafe-inline` e `unsafe-eval` são proibidos; conexões, frames, objects, formulários e mídia são default-deny no fixture atual. A configuração não define `devUrl`, `webviewUrl` ou navegação remota.

## Limites explícitos

- Esta ADR não transforma o MVP single-process em sandbox ou site isolation.
- A surface de página/Servo está fora da WebView Tauri privilegiada nesta Issue.
- Não há implementação de comandos Tauri reais neste card; o `IpcBridge` é o contrato de validação engine-neutral.
- Nenhuma capability é liberada para fazer PR-045 passar; ausência de evidence permanece NO_GO.

## Consequências

### Positivas

- Uma página, iframe, janela errada ou generation stale não consegue reutilizar a bridge privilegiada.
- A configuração deixa explícita a ausência de filesystem/network/process/plugin access.
- A CSP fixture é verificável por teste Rust e não depende de inspeção manual do HTML.

### Negativas e riscos aceitos

- A UI não pode usar APIs Tauri até uma capability mínima e um comando tipado serem aprovados.
- O origin/protocol exato do WebView deve ser revalidado se o backend Tauri mudar.
- Isolamento de processo e engine host separado continuam gates de Stable.

## Evidência

- `apps/desktop/src-tauri/capabilities/main.json` contém `permissions: []` e limita a janela `main`.
- `tauri.conf.json` usa CSP sem `unsafe-inline`/`unsafe-eval`, sem `devUrl` e sem URL de janela.
- `browser-core::ipc_bridge` testa rejeição por origin, window, iframe e generation sem consumir o request.
- `browser-desktop` testa JSON de capability/CSP e ausência de navegação remota.

## Revisão / ratificação

A decisão permanece `proposed` até PR-024/045 terem integração Tauri real com commands tipados e evidência de shell em pelo menos Linux e outra plataforma. Qualquer plugin, capability não vazia, URL remota ou comando genérico reabre a revisão.
