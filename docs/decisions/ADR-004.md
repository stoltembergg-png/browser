# ADR-004 — Provisional engine API contract

- **Status:** accepted (ratified)
- **Date:** 2026-08-13
- **Owners:** repository maintainers
- **Related PRs:** PR-015, PR-016, PR-026
- **Related threats/tests:** contract suite red/green, unknown version rejection, cancellation, terminal results, capability negotiation

## Contexto

O spike PR-013 provou a viabilidade do embedding do Servo. O spike PR-014 provou a viabilidade do render surface. PR-015 define o contrato mínimo pós-surface e um testkit fake engine para validar o contrato sem depender do Servo real.

O contrato é **provisional**: não congela extensões de permission, download, popup ou DevTools. Essas entram somente após capability negotiation, policy do core e testes negativos (ARCHITECTURE.md §6).

## Decisão

O contrato engine-api v1 define:

### Commands (core → engine)
- `Navigate`, `Reload`, `GoBack`, `GoForward`, `Stop`, `SetViewport`, `Input`, `Shutdown`

### Events (engine → core)
- `EngineStarted`, `EngineReady`, `EngineExited`, `EngineCrashed`
- `NavigationStarted`, `NavigationCommitted`, `NavigationFinished`, `NavigationFailed`, `NavigationCancelled`
- `TitleChanged`, `FrameReady`
- `CommandCompleted`, `CommandCancelled`, `CommandTimedOut`
- `QueueSaturated`

### Erros tipados
- `EngineError` com variantes: `UnknownCommand`, `UnknownVersion`, `InvalidPayload`, `NotSupported`, `EngineCrashed`, `Timeout`, `Cancelled`

### Capabilities
- `EngineCapabilities` declara quais operações o engine suporta
- Comandos fora do subset suportado são rejeitados com `NotSupported`

### Lifecycle
- States: `Created → Starting → Ready → Navigating → Closing → Exited`
- Failure states: `Failed`, `Crashed`
- Recovery: `Restarting` (policy permitting)
- Qualquer transição não listada falha fechado

### Versionamento
- `ENGINE_API_VERSION = 1`
- Unknown versions são rejeitadas
- Breaking changes exigem version bump e ADR de superseding

## Limites explícitos

- Sem `EvaluateScript`, `DevTools`, grants de permission, decisões de download, popup ou dialog
- Sem tipos Servo no contrato
- Sem IPC real — channels locais no MVP
- O contrato não ratifica extensões fora do subset; novas capabilities exigem ADR e testes próprios.

## Alternativas consideradas

1. **Contrato completo desde o início** — muito arriscado sem evidência do adapter real (PR-016)
2. **Sem versionamento** — quebra compatibilidade silenciosamente
3. **Contrato não-tipado** — viola o princípio de security-by-design

## Consequências

### Positivas
- O fake engine pode testar o contrato sem Servo
- O adapter real (PR-016) implementa o mesmo contrato
- Versionamento permite evolução controlada

### Negativas e riscos aceitos
- O subset ratificado é deliberadamente pequeno e pode evoluir por ADR de superseding
- Breaking changes exigem ADR de superseding
- Sem extensões fora do subset sem capability negotiation

## Ratificação

A decisão foi ratificada após:
- PR-016 produzir o adapter engine-neutral passando o contrato;
- a contract suite cobrir unknown versions, cancellation, terminal results e capability negotiation;
- PR-026 compilar o backend Servo pinado e executar fixture real com frame/readiness, input, resize, thread affinity e shutdown, com artifact validado por `scripts/servo_evidence_check.py`.
